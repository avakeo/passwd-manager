# 楕円曲線暗号ノート

チーム用パスワードマネージャーの設計で使う、楕円曲線暗号（P-256）の仕組みを小さな数字で整理したメモ。数値はすべて実際に計算して確かめたもの。

---

## 1. 登場する値と役割

| 値 | 意味 | 公開／秘密 | 誰が決めるか |
|---|---|---|---|
| p | 素数（prime number）。計算はすべて「p で割った余り」で行う | 公開 | 規格 |
| a、b | 曲線の式 y² = x³ + ax + b の係数 | 公開 | 規格 |
| G | 出発点。曲線上の決まった1点 | 公開 | 規格 |
| n | G を何回足すと一周して戻るか | 公開 | 規格 |
| sk | 秘密鍵。ただの数（乱数） | **秘密** | 各自の端末が乱数で選ぶ |
| pk | 公開鍵。G を sk 回足した点（sk × G） | 公開 | 計算で決まる |

- 秘密なのは sk だけ。それ以外はすべて公開。
- 「P-256 を使う」と言った時点で、p、a、b、G、n はすべて決まる。
- p は prime number の p で、パスワードとは無関係。公開鍵 pk の p とも別物。
- G は p だけでは決まらない。曲線は p、a、b で決まり、G はその曲線上の点から規格が1つ選んだもの。

---

## 2. 「p で割った余りの世界」とは

時計と同じ考え方。12時間の時計では、10時の5時間後は15時ではなく3時になる（12で割った余り）。同じように、すべての計算結果を p で割った余りにする。

これで次の性質が得られる。

- 小数が出ない（整数だけで正確に計算できる）
- 点の数が有限になる
- 足し算の結果がでたらめな場所に跳ぶ（逆算が難しくなる）

割り算は「掛けると1になる数を掛ける」に置き換える。例：17で割った余りの世界では、2 × 9 = 18 の余りが1なので、「÷2」は「×9」と同じ。

---

## 3. 最小の例：17で割った余りの世界

- 曲線：y² = x³ + 2x + 2（p = 17、a = 2、b = 2）
- この式を満たす点は18個
- 出発点 G = (5, 1)

### 曲線上の18個の点

(0, 6)、(0, 11)、(3, 1)、(3, 16)、(5, 1)、(5, 16)、(6, 3)、(6, 14)、(7, 6)、(7, 11)、(9, 1)、(9, 16)、(10, 6)、(10, 11)、(13, 7)、(13, 10)、(16, 4)、(16, 13)

### G を1回ずつ足していくと（kG の一覧）

| k | kG | k | kG |
|---|---|---|---|
| 1 | (5, 1) | 10 | (7, 11) |
| 2 | (6, 3) | 11 | (13, 10) |
| 3 | (10, 6) | 12 | (0, 11) |
| 4 | (3, 1) | 13 | (16, 4) |
| 5 | (9, 16) | 14 | (9, 1) |
| 6 | (16, 13) | 15 | (3, 16) |
| 7 | (0, 6) | 16 | (10, 11) |
| 8 | (13, 7) | 17 | (6, 14) |
| 9 | (7, 6) | 18 | (5, 16) |
| | | 19 | ゼロ（無限遠点。一周して戻る） |

番号が隣どうしでも、場所がまったく似ていない。たとえば 12G = (0, 11)、13G = (16, 4)、14G = (9, 1)。これが「でたらめに跳ぶ」ということ。

## 4. 点の足し算のルール

### 点を自分自身に足す（2倍）

すべて p で割った余りで計算する。

1. 傾き λ ＝（3x² + a）÷（2y）
2. 新しい x ＝ λ² − 2x
3. 新しい y ＝ λ ×（元の x − 新しい x）− 元の y

### 異なる2点を足す

1. 傾き λ ＝（y₂ − y₁）÷（x₂ − x₁）
2. 新しい x ＝ λ² − x₁ − x₂
3. 新しい y ＝ λ ×（x₁ − 新しい x）− y₁

### 手計算の例：G + G = 2G

G = (5, 1)、a = 2、p = 17。

| 手順 | 計算 | 17で割った余り |
|---|---|---|
| 分子 | 3 × 5² + 2 = 77 | 9 |
| 分母 | 2 × 1 = 2。「÷2」は「×9」 | — |
| λ | 9 × 9 = 81 | 13 |
| 新しい x | 13² − 2 × 5 = 159 | 6 |
| 新しい y | 13 ×（5 − 6）− 1 = −14 | 3 |

結果：**2G = (6, 3)**（一覧表と一致する）

### 式の出どころ

この式は P-256 独自のルールではなく、楕円曲線全般に共通する数学の公式。高校数学で導ける。余りを取らない普通の曲線で考えると、次の図形の操作を式にしたもの。

1. **接線を引く**（異なる2点なら、2点を通る直線を引く）
   - 曲線の式を微分すると、接線の傾きは（3x² + a）÷（2y）になる
2. **直線が曲線とぶつかる3つ目の点を探す**
   - 直線の式を曲線の式に代入すると x の3次方程式になる。3つの解の合計は λ²（解と係数の関係）。接点では2つの解が重なるので、3つ目は λ² − 2x
3. **その点を上下に反転する**（y の符号を変える）
   - 足し算として矛盾しないルールにするための約束

余りを取る世界でも式はそのまま使える。ただし余りを取るせいで図形の見た目は崩れ、結果がでたらめな場所に跳ぶ。

## 5. 鍵ペアと「一方向性」

- 秘密鍵 sk：乱数で選んだただの数
- 公開鍵 pk：G を sk 回足した点

鍵ペアの生成は暗号化ではなく、「乱数を1つ選び、G にその回数を掛ける」計算。

### sk → pk は速い

2倍にする操作を組み合わせるので、31415倍でも約20回の足し算で済む（31415 を2進数で表すと15桁なので、2倍を15回と、足し算を数回）。

### pk → sk は遅い

例：pk = (16, 4) から sk を求めたい。

- 普通の数なら、「13 × 5 = 65」から 65 ÷ 5 で13にすぐ戻れる。値が順番に大きくなるので、割り算や絞り込みができる
- 楕円曲線では、kG から k を求める割り算は存在しない。近い番号でも場所が似ていないので絞り込みもできない。G、2G、3G…と順に足して、(16, 4) が出るまで待つしかない（答えは13）

この「kG から k を求める問題」を**楕円曲線上の離散対数問題**と呼ぶ。

| 曲線の大きさ | 点の数 | 総当たり |
|---|---|---|
| p = 17 | 18個 | 一瞬 |
| p = 100003 | 99,707個 | 0.04秒（実測） |
| P-256 | 約 10⁷⁷ 個 | 約 2¹²⁸ 回の計算。宇宙の年齢でも終わらない |

**安全性は「ルールを隠すこと」ではなく、「ルールを全部公開しても逆算できないこと」で成り立っている。**（ケルクホフスの原理）

## 6. 少し大きい例：p = 100003

- 曲線：y² = x³ + x + 5（p = 100003、a = 1、b = 5）
- 点の数 n = 99,707（素数なので、どの点から足しても全点を回れる）
- 出発点 G = (2, 86328)
- 2G = (28333, 76758)、3G = (85148, 29034)

### 鍵ペア

| | 秘密鍵 | 公開鍵 |
|---|---|---|
| Aさん | 31415 | (24436, 76404) |
| Bさん | 27182 | (48552, 71481) |

### ECDH（鍵交換）

- Aさんは「自分の秘密鍵 × Bさんの公開鍵」を計算 → **(642, 44637)**
- Bさんは「自分の秘密鍵 × Aさんの公開鍵」を計算 → **(642, 44637)**

どちらも「31415 × 27182 × G」を別の順番で計算しているので同じ点になる。盗聴者に見えるのは2つの公開鍵だけで、秘密鍵を知らないのでこの点を計算できない。**会わずに同じ合鍵を作る仕組み。**

このプロジェクトでは、Vault 鍵をメンバーに渡すとき（A-2、HPKE）にこの仕組みを使う。

## 7. 本物の P-256

| 値 | 内容 |
|---|---|
| p | 2²⁵⁶ − 2²²⁴ + 2¹⁹² + 2⁹⁶ − 1（78桁） |
| a | −3 |
| b | 規格で決まった大きな数 |
| G | x が 6b17d1f2e12c4247… で始まる、規格で決まった点 |
| n | 規格で決まった78桁の素数 |
| 秘密鍵 | 77桁ほどの乱数 |
| 公開鍵 | 65バイト（先頭の 04、x の32バイト、y の32バイト） |

仕組みは小さな例とまったく同じで、数が大きいだけ。

実装の注意：点の計算を自分で書いてはいけない。素朴に実装すると、計算時間の差から秘密鍵が漏れる（サイドチャネル攻撃）。計算は WebCrypto に任せる。

## 8. RSA との違い

### RSA を小さな数で

- 秘密の素数 61 と 53 を掛けて n = 3233（公開）
- 公開指数 e = 17（公開）、秘密指数 d = 2753（秘密）
- 65 を暗号化：65¹⁷ を3233で割った余り = **2790**
- 2790 を復号：2790²⁷⁵³ を3233で割った余り = **65**

3233 が 61 × 53 だと分かれば d を計算できてしまう。RSA の安全性は**巨大な数の素因数分解が難しいこと**に頼っている。

### 比較

| | RSA | P-256（楕円曲線暗号） |
|---|---|---|
| 難しさの根拠 | 巨大な数の素因数分解 | kG から k を求めること（離散対数） |
| 同じ強さに必要な鍵の長さ | 3072ビット（10進で約925桁） | 256ビット（約77桁） |
| 公開鍵の大きさ | 約384バイト | 65バイト |
| 鍵の生成 | 遅い（巨大な素数を探す） | 速い（乱数を選んで G に掛けるだけ） |
| できること | 暗号化と署名 | 鍵交換（ECDH）と署名（ECDSA）。暗号化は「ECDH で合鍵を作って AES」 |
| WebCrypto での名前 | RSA-OAEP（暗号化）、RSA-PSS（署名） | ECDH、ECDSA |
| 量子計算機 | 破られる | 破られる |

### 歴史

| 年 | 出来事 |
|---|---|
| 1977年 | RSA が発表される |
| 1985年 | 楕円曲線暗号が提案される（Koblitz と Miller がそれぞれ独立に） |
| 2000年 | NIST の標準規格で P-256 などの曲線が定められる |
| 2018年 | TLS 1.3 で RSA による鍵交換が廃止され、鍵交換は ECDHE などに |
| 2024年 | 量子耐性のある新しい標準（ML-KEM、ML-DSA）が NIST で正式に定まる |

P-256 は RSA の「後任」ではなく並行して使われてきた方式。ただし鍵交換では楕円曲線が主流になり、署名でも増えている。次の世代は、両方の後任としての量子耐性方式。

### このプロジェクトで P-256 を選んだ理由

- 鍵が短い：公開鍵もフィンガープリントも短く、承認時の照合が楽
- 鍵の生成が速い：ブラウザで鍵ペアを作るときに待たされない
- HPKE の標準に合う：HPKE は「鍵交換で合鍵を作り、AES で暗号化する」形が前提

## 9. 暗号の部品の役割

| 名前 | 分類 | 何をするか | たとえ |
|---|---|---|---|
| PBKDF2 | 鍵導出（パスワード用） | 覚えた言葉から鍵を作る。わざと遅い | 合言葉から鍵を時間をかけて削り出す |
| HKDF | 鍵導出（鍵用） | 1本の鍵から用途別の鍵を作る。速い | 親鍵から用途別の合鍵を作る |
| AES-GCM | 対称鍵暗号（認証付き） | 同じ鍵で暗号化と復号。改ざんも検知 | 金庫。同じ鍵で閉めて開ける |
| P-256 | 楕円曲線（公開鍵暗号の土台） | 鍵ペアを定義する。それ自体は暗号化しない | 鍵ペアを作るための計算のルール |
| ECDH | 鍵交換 | 自分の秘密鍵と相手の公開鍵から、2人だけの共有秘密を作る | 会わずに同じ合鍵を作る方法 |
| SHA-256 | ハッシュ | データから固定長の値を一方向に作る | 指紋。PBKDF2 と HKDF の中でも使われる |

## 10. A-1（鍵ペアの生成と保存）を実際の数字で

### パスワード側の流れ

1. 利用者がマスターパスワードを決める（例：sakura-kumo-ringo-73）。ランダムに作るのはパスワードではなくソルト
2. ソルト（16バイトの乱数）：9f2c4a71e03b5d88c16a2f0b7e4d9153。平文で保存してよい
3. PBKDF2（SHA-256、60万回）→ マスターキー
   - 38d5abadb6cb86b564900a8617282da0154aa5379199891c5a70e27f1796a81c
   - 1文字違い（…-74）だと 6affdbc656f4c8d2… とまったく別の値
   - 出力は暗号文ではなく鍵。元のパスワードには戻せない
4. HKDF（用途ラベル teampw/v1/private-key-wrap）→ ラップ鍵
   - c429d7672a1cb36e972dfe3788e55107b922e49c002d099f03c004a1dabfe253
   - 別のラベルなら aceac3620fd093f3… と別の鍵になる（ドメイン分離）

### 鍵ペア側の流れ（パスワードとは独立）

5. P-256 の鍵ペアを乱数から生成する
   - 秘密鍵（77桁）：62959851324257542584805810004659076169591458047909207254651228379856561577241
   - 公開鍵 x：46749387051993978084910577706322439418722029122079100901817284889689444358162
   - 公開鍵 y：15385064884553841494372430373701728411482615718101619707862451283578032743044

鍵ペアをパスワードから作らない理由：

- パスワードを変えても鍵ペアを変えずに済む（秘密鍵を暗号化し直すだけ）
- 鍵の強さがパスワードの強さに左右されない

### 合流

6. 秘密鍵を PKCS#8 形式（138バイト）に書き出し、ラップ鍵で AES-GCM 暗号化する
   - ノンス：3b7e19c04a52d6f8e1a09c27
   - AAD：v1|member-key|key_7f3a|70dd2685e8369120b12da8c33d6fbde7a0d9215389fe4f47efd151147a4b8110（最後は公開鍵の SHA-256。2026-10-17 に足した）
   - 暗号文：154バイト（138バイト ＋ 認証タグ16バイト）
7. 公開鍵（65バイト）の SHA-256 をフィンガープリントにする（70dd2685e8369120b12d…）

### 保存するもの・しないもの

| D1 に保存する | どこにも保存しない |
|---|---|
| 公開鍵 | マスターパスワード |
| 暗号化した秘密鍵とノンス | マスターキー |
| ソルト | ラップ鍵 |
| KDF パラメータ（PBKDF2-SHA256、60万回） | 秘密鍵の平文 |

### 間違ったパスワードの場合

別のラップ鍵になるので、AES-GCM の認証タグの検証で復号に失敗する。パスワードの正誤を確かめるための別のハッシュを保存する必要はない。
