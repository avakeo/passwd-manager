# KeePassXC との比較

- 日付：2026-11-03
- 比べた資料：KeePassXC の公開情報（リリースノート、リポジトリ）
- 選んだ理由：サーバーを持たない方式の代表。teampw の「サーバーを信じない」設計と、そもそもサーバーを置かない設計を比べる

## 1. 仕組みの比較

| 項目 | teampw | KeePassXC |
|---|---|---|
| データの置き場所 | Cloudflare D1（暗号文） | 手元の KDBX ファイル。同期は利用者が別に行う（クラウドのストレージなど） |
| 鍵の導出 | PBKDF2-HMAC-SHA256 60万回 | KDBX 4 では Argon2d か Argon2id、または AES-KDF |
| 暗号 | アイテムごとに AES-256-GCM | ファイル全体を AES-256、ChaCha20、Twofish のどれかで暗号化する |
| チームでの共有 | 管理者の承認、グラント、ローテーション | 同じファイルとマスターキーを渡す。KeeShare でグループごとにファイルを分けて共有できる |
| 権限と取り消し | 承認済みのメンバーだけが API を使える。外したら Vault 鍵を作り直す | ファイルとマスターキーを持つ人は全件を読める。取り消すには、マスターキーを変えて配り直す |
| 自動入力 | 拡張機能のポップアップから | KeePassXC-Browser（ネイティブメッセージングで本体とつなぐ） |

## 2. KeePassXC のほうが強い所

- サーバーへの攻撃がそもそもない。悪意あるサーバーの論文の攻撃は、どれも当てはまらない。teampw が照合、署名、世代の記録、リビジョンで防いでいる攻撃が、最初から起きない。
- 総当たりへの強さ。Argon2 を選べる。
- 実績。長く使われ、オープンソースで、多くの人が読んでいる。

## 3. teampw のほうが合う所

- チームの出入り。KeePassXC では、外した人は古いファイルとマスターキーを持ったままになる。teampw も外した人の端末に残った古いデータは消せないが、Vault 鍵を作り直すので、外した後に足したアイテムと、変えたパスワードは読めない。新しい鍵を配り直す手間も、承認の画面とグラントで済む。
- 同時編集。KeePassXC は、同じファイルを2人が書き換えると、同期の側でぶつかる。teampw はリビジョンで409を返し、選ばせる（S-01）。
- 誰が何をしたか。teampw は監査ログを持つ。

## 4. 学んだこと

- 「サーバーを信じない」設計は、サーバーを置かない設計に比べると、守る所が多い。teampw の照合、署名、世代の記録、ローテーションのバッチは、どれもチームでの共有と出入りのために要るもので、1人で使うなら KeePassXC の形のほうが単純で強い。
