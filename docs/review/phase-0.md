## 観点表で見てほしい所

| 観点 | 見てほしい所 |
|---|---|
| 署名する中身 | 受け手は、宛先のメンバー ID・鍵 ID・公開鍵のハッシュ、署名者を、グラントの行ではなく自分の値と固定値から組み立てる（grant.ts の `verifyGrant`） |
| 確かめる順 | 固定 → 署名者の鍵 ID → 署名の形 → 世代 → 宛先 → 署名の検証 → HPKE → 世代の記録。署名を確かめない開封の入口は export しない（P-01 の export の検査） |
| 取り出し不可 | 署名用秘密鍵は生成時だけ取り出し可。ロック解除後は取り出し不可・用途 sign だけ（C-16）。署名用公開鍵は取り出し不可・用途 verify だけで読み込む |
| ドメイン分離 | 署名のラベル `teampw/v1/grant-signature`、署名鍵のラップ鍵のラベル `teampw/v1/sign-key-wrap`、AAD の種別 `admin-sign-key` |
| エラー | 署名の失敗は DECRYPT_FAILED と分けたが、どのフィールドが違うかまでは返さない |
| サーバー | サーバーは署名を検証しない。承認とローテーションの API はフェーズ4で作るので、署名の列の形の検査（400）もそのときに足す |

## 残したこと

- 承認とローテーションの API（署名の列の形の検査を含む）はフェーズ4。今回は、D1 の列と取得の API、暗号コアまで。
- マスターパスワードの変更（署名用秘密鍵の暗号化し直し）は、ECDH の秘密鍵の変更と一緒に作る（まだどちらもない）。
- 固定と世代の保存先は、提出版の固定と同じくインターフェースとメモリ上の実装だけ。拡張機能で chrome.storage.local に差し替える。
