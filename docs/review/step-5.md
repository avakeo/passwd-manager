## 対応する仕様の節

- 暗号仕様 > Vault鍵の受け渡し（RFC 9180 Base、info と aad、ノンスは鍵スケジュールから、Extract/Expand の組み方、使い捨て秘密鍵の扱い）
- 暗号仕様 > 共通の規則（グラントの保存形式、アルゴリズムID 0x02）
- 鍵のライフサイクル（Vault 鍵の通常利用は取り出し不可、管理操作だけ取り出し可として開き直す、使い捨て鍵ペアは破棄）

## テストを後から書いたことの記録と、わざと壊して確かめた結果（2026-10-16）

この手順では、本体（hkdf.ts、hpke-core.ts、hpke.ts、public-key.ts、grant.ts）をテストより先に書いた。コミット 6db942f と c4c7d69 は、テストを書いて全部通ってから作ったが、「テストを先に書く」という進め方は守れていない。コミットの順番と中身は書き換えず、ここに記録する（2026-10-16 に、全コミットの作者のメールアドレスだけを変えたので、コミット ID はこのとき変わった（順番と中身は変えていない））。

その代わりに、テストが本当に実装の誤りを捕まえるかを確かめた。手順5の実装を1か所ずつわざと壊し、C-13（暗号コアだけのもの、API 経由のもの）と C-15 を実行した。壊すたびに `git checkout` で元に戻し、作業ツリーに差分が残っていないことを確かめている。

### 分かったこと

- **C-13 は往復のテスト**なので、送り手と受け手の食い違い（M1、M5）は捕まえるが、両側を同じように変えた誤り（M2、M3、M4）は捕まえない。自分の実装どうしでは、往復が成り立ってしまうため。
- **RFC 9180 からのずれ（M3、M4、M5）は C-15 が捕まえる**。公開テストベクタは、ほかの実装と同じ値になることを求めるので、両側を同じように変えても落ちる。
- **info の形の誤り（M2）は C-13 でも C-15 でも捕まらない**。info はこのプロジェクト独自の値で、公開ベクタには出てこないため。単体テスト「info は teampw/v1/vault-key-grant|世代|宛先の鍵ID」だけが捕まえる。ほかの実装（将来の拡張機能など）と互換性を保つには、この単体テストが必要。

## レビューの指摘と対応（2026-10-17）

手順5について、Codex（仕様の照合）と、攻撃者の目線のレビュー（docs/review/攻撃者の目線レビュー.md）を受けた。この節には、手順5に関わる指摘を全部書く。攻撃者レビューの #2（公開鍵の固定）と #4（検査テスト）は手順6に関わるので、step-6.md に書いた。直したのはブランチ fix/review-step5-6 で、採用した指摘ごとに、失敗するテストを先に書いてからコミットした（#1 と Codex #5 は、コードを直さずテストを足す対応）。

### Codex のレビュー

観点表の8項目のうち、手順5で判断できる7項目は「守れている」、KDF の下限は手順5の範囲外で「判断できない」だった。C-15、C-13、C-06、C-12 は中身も仕様どおり。重大度「高」の指摘はなかった。

| # | 重大度 | 指摘 | 判定 | 対応・理由 |
|---|---|---|---|---|
| 1 | 中 | `keyScheduleBase` の `keyScheduleContext` と `baseNonce` を wipe していない。`baseNonce` は HpkeContext に残り、消す経路がない | 不採用 | `baseNonce` と `keyScheduleContext` からは、包み用の鍵を作り直せない（指摘にも「実害は薄い」とある）。鍵を作り直せる `key` と `secret` は wipe している。JavaScript ではコピーや GC があるので、wipe は確実な消去にならず、消す範囲を広げても守れるものが増えない |

| 5 | 低 | info のラベルの誤り（M2）は C-13 でも C-15 でも捕まらず、単体テストだけが守っている | 採用 | 既知解テストを足した（コミット 033e009）。固定の受け手と使い捨ての鍵ペア、世代、鍵ID、Vault 鍵からグラントを作り、決まった enc と wrapped_key になることを確かめる。開く側も、決まったグラントから決まった Vault 鍵になることを確かめる。期待値は src を使わず、node:crypto で RFC 9180 の SealBase を別に組んで計算した。M2 と同じ壊し方（ラベルを vault-key-grans に変える）をすると、既知解テスト2件が落ちることを確かめた |
| 6 | 情報 | HPKE ベクタのライセンスの扱いは、例外として仕様書に書かれていて、手続きとして整合している | 不採用 | 直す点の指摘ではないので、対応はしない |
