# 攻撃者の目線レビュー：管理者署名（グラントの送り手認証）

- 日付：2026-10-17
- 対象：ブランチ feat/admin-signature（攻撃者レビュー #1・#7 の対応差分）
- 設計：docs/設計案_グラントの送り手認証.md、docs/review/phase-0.md
- 前提：攻撃者はサーバー（D1 と Workers）を乗っ取り、保存されたデータと API の応答を自由に書き換えられる。端末とマスターパスワードは攻撃者の手にない
- 見たファイル：`src/crypto/grant.ts`、`src/crypto/signer.ts`、`src/crypto/member-key.ts`、`src/crypto/format.ts`、`src/crypto/errors.ts`、`src/crypto/kdf.ts`、`src/crypto/public-key.ts`、`src/crypto/bytes.ts`、`src/crypto/hpke.ts`、`src/api/app.ts`、`src/api/auth.ts`、`migrations/0001_init.sql`、`tests/crypto/grant.test.ts`、`tests/crypto/signature.test.ts`、`tests/api/e2e.test.ts`

## 結論

署名の検証そのもの（署名する中身の再構成と、固定した公開鍵での照合）には、飛ばす入口も衝突も見つからなかった。破れるのは「署名の外側」、つまり固定・世代・API の隙である。

## 補足

- 署名の検証ロジック自体は堅く、#3（固定の正当性）以外に偽造を通す道は見つからなかった。
- #1・#2・#7・#8 は設計案 11章の「新しい世代を隠す／初期化直後」の既知リスクの鋭い変種で、初回ロード全般・広告世代との不一致・管理者操作時まで及ぶ点が未記載。
- #5 と #6 が、依頼の「/v1/me の余計な情報」と「エラーの違い」に直接対応する。
