# 手順2 A-4 アイテム：レビュー資料

## 変更したファイル

| ファイル | 中身 |
|---|---|
| src/crypto/aead.ts | AES-256-GCM の暗号化と復号。ノンスは暗号化のたびにこの中で乱数を作る。外からノンスを渡す口はない |
| src/crypto/vault-key.ts | Vault 鍵の生成（生の32バイト）と、取り出し不可での読み込み |
| src/crypto/item.ts | パディング、アイテムの暗号化と復号 |
| tests/crypto/item.test.ts | C-02、C-03、C-04、C-05、C-08、C-09 と、上限、長さの値の検査 |

## 対応する仕様の節

- 暗号仕様 > アイテムの暗号化（パディングの単位と方式、AAD、ノンス）
- 暗号仕様 > 共通の規則（保存形式、取り出し不可）
- 暗号仕様 > 鍵のライフサイクルと取り出し可否（Vault 鍵の通常利用は取り出し不可）

## テスト ID

| ID | テスト |
|---|---|
| C-02 | 暗号化と復号の往復 |
| C-03 | 本体、ノンス、認証タグの1ビットの改ざん。さらに、ヘッダー以外の全バイトを1ビットずつ改ざんする |
| C-04 | 別のアイテムIDの場所に移す |
| C-05 | 鍵の世代を書き換える |
| C-08 | 5,000回暗号化してノンスがすべて異なる。同じ内容でも暗号文が異なる |
| C-09 | 暗号文の長さが「パディング単位 ＋ 30バイト」の5種類だけになる。境界（508/509、65,532 など）も確かめる |

## 観点表で見てほしい所

| 観点 | 見てほしい所 |
|---|---|
| ノンス | `aesGcmEncrypt` は引数でノンスを受け取らない。テストでノンスを固定する経路はない |
| AAD | `itemAad` で ID と世代を検査してから組み立てる。復号側でも、D1 の行（id、vault_key_version）から毎回作り直す |
| 取り出し不可 | `importVaultKey` は extractable を false にしている |
| エラー | 長さの値が範囲外、パディング単位でない大きさ、JSON として読めない、type が login と note 以外、のどれも DECRYPT_FAILED にまとめた |
| パディング | 長さの値の上限は「パディング後の大きさ − 4」。それより大きければ失敗にする |
| メモリ | 平文の JSON とパディング後のバイト列は、使い終わったら0で上書きする。ただし JSON.stringify の文字列や、呼び出し側が持つオブジェクトは消せない（JavaScript の限界） |
