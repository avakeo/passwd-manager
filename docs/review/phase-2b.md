## レビューの指摘と対応（2026-10-27）

PR #6 の Codex のレビュー（docs/review/phase-2b_codex.md）と、DeepSeek の攻撃者の目線レビュー（docs/review/phase-2b_deepseek.md）の全指摘と、判定、対応。対象はどちらも `30d1e81`。採用したものは、先に失敗するテストを書いて落ちることを確かめてから直した。対応の後、`npm test` 427件すべて成功、`npm run typecheck` 成功、`npm run test:browser` 4件成功。

2つのレビューの指摘は重なっている（Codex #1 と DeepSeek #3、Codex #2 と DeepSeek #4、Codex #3 と DeepSeek #2）。どれも 2a の Codex #3「時間のかかる処理は、終わった時点でロックを確かめる」が、2b で足した経路に届いていなかったもので、1つのコミットで直した。

### Codex

| # | 重大度 | 指摘 | 判定 | 対応 |
|---|---|---|---|---|
| 1 | 高 | quickUnlock は、失敗の回数を戻す storage の読み書きを待っている間にロックされても、その後に Vault 鍵を置いて ready を返す | 採用 | 回数を戻した後、鍵を置く直前にもう一度確かめる（8ed14e8） |
| 2 | 高 | getItem は復号の後にロックを確かめず、ロックの後も平文を返す。sync も復号の後に一覧へ書く | 採用 | getItem は復号の後に確かめる。saveItem・deleteItem も通信の後に確かめる。loadCache・putEntry・sync は、復号の後に待たずに確かめてから一覧に書く（8ed14e8） |
| 3 | 中 | 同期どうしが重なると、遅れて終わった古い応答が、新しい版とカーソル・最後に見た Vault リビジョンを巻き戻す | 採用 | 手元の版より古いリビジョンでは書き換えない。カーソルと最後に見た Vault リビジョンは大きい方を残す（8ed14e8） |
