## 手で確かめる項目

| 項目 | 確かめ方 |
|---|---|
| マイグレーション 0003 | 開発用の D1 に `npx wrangler d1 migrations apply teampw-dev --remote`、`npx wrangler deploy` |
| アイテムの作成・編集・削除 | 全画面ページで、ログインとメモを作り、開いて直し、削除する。ポップアップの一覧にタイトルとユーザー名だけが出ること |
| S-01 | 2つ目の Chrome のプロファイルで同じ管理者でログインし、同じアイテムを両方で開いて保存する。後の方に「ほかの人が先に変更しました」と今の版・自分の入力が並び、選べること |
| S-02 | 一方で削除し、もう一方で全画面ページを開き直すと消えていること |
| クイックロック解除 | 全画面ページで4桁を決める。chrome://serviceworker-internals で Service Worker を止め、ポップアップがパスコードで解除できること |
| E-15 | わざと5回間違え、パスコードの欄が消えてマスターパスワードを求められること |
| E-17 | パスコードで戻った状態で、鍵の作り直しを押すとマスターパスワードを求められること |
| E-18 | ブラウザを閉じて開き直すと、パスコードが使えないこと |
| 放置のロック | パスコードで戻った後、15分触らないとロックされること（ポップアップを開いたままにしても、同期では延びないこと） |
| HTML として解釈しない | タイトルやメモに `<img src=x onerror=alert(1)>` を入れて保存し、文字として出ること |
| 2つ目の端末の世代 | 2つ目のプロファイルの管理者は、端末を初期化した扱いで「世代の初期化（対面の照合）」が要る。照合の画面はフェーズ4なので、今は1台目の storage.local の固定を写すか、1台目だけで確かめる |
| 悪意ある拡張機能（2a から） | phase-2a.md の webRequest と debugger の手順。storage.session の包んだ Vault 鍵も、debugger の権限があれば読めることを記録する（範囲外の表） |

## 観点表で見てほしい所

| 観点 | 見てほしい所 |
|---|---|
| 鍵の置き場所 | background.ts の `vaultKey`・`unlocked`・`index`（一覧の平文）はメモリだけ。storage.local の `teampw/v1/sync\|…` は暗号文だけ。storage.session の `teampw/v1/unlock\|…` は包んだ Vault 鍵だけ |
| クイックロック解除 | `reserveAttempt`（試す前に数える）と `serialized`（1つずつ順に）。5回目の失敗での消去。`unlockedBy === 'passcode'` のときの PASSWORD_REQUIRED |
| 同期 | sync の巻き戻しの検知、新しい世代の扱い、カーソル（change_seq）。PASSIVE_TYPES に sync と listItems |
| 409 | conflictReply（同期してから今の版を返す。自動で送り直さない） |
| 入力の検査 | messages.ts の item（validateItem を通した値だけ）と、openEntry の復号した後の validateItem |
| Playwright | 足したパッケージは3つ。ブラウザは Playwright の Chromium（`npx playwright install chromium`）。CI には入れていない（重いので、手元の `npm run test:browser`） |
