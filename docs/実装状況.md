## 3. 観点表（実装計画の3章）で注意する所

コードがないので「怪しい所」はまだない。代わりに、実装するときに間違えやすい所を先に書いておく。レビューでもここを重点的に見る。

| 観点 | 間違えやすい所 |
|---|---|
| ノンス | テストで固定のノンスや使い捨て秘密鍵を差し込む仕組みを、本体の経路に残さない。テストベクタを確かめる専用の関数にだけ渡せるようにする。グラントは HPKE の鍵スケジュールからノンスを作るので、乱数のノンスを持たない |
| AAD | `\|` 区切りだと、ID に `\|` が入ったときに曖昧になる。ID に使える文字を `[A-Za-z0-9_-]` に限る（仕様書「共通の規則」）。復号の前に、ヘッダーの形式バイトと AAD の形式が一致することを確かめる |
| 取り出し不可 | 読み込むときに extractable を false にし忘れない。取り出し可にするのは、鍵のライフサイクルの表にある管理操作だけ |
| KDF の下限 | 下限の確認は、PBKDF2 を計算する前に行う。種類（PBKDF2-SHA256 以外）も拒否する |
| HKDF のラベル | 秘密鍵用のラベルと HPKE 内部のラベル（RFC の `HPKE-v1` 系）が重ならないようにする |
| 公開鍵の固定 | 比較はバイト列で行う。比較が通る前にグラントを作らない |
| 乱数 | Math.random を使わない。getRandomValues の呼び出しは1か所にまとめる |
| エラー | パスワードの誤りと改ざんで、失敗の種類やメッセージを分けない |
